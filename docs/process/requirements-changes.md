# Requirements Changes

Each entry: date, change, reason, source. Changes before 2026-10-01 are reconstructed from `docs/handoff.md`.

| Date | Change | Reason | Source |
| --- | --- | --- | --- |
| before 2026-10-01 | Automatic daily digest → manual "Generate Digest" covering the period since the last successful request | Simpler first release; users who check less often still get everything since their last digest | handoff §4 |
| before 2026-10-01 | Scope narrowed from "any website" to selected public sites/blogs and podcasts/videos with accessible transcripts | Arbitrary scraping is unreliable; summarizing audio/video without transcripts would overclaim | handoff §3 |
| before 2026-10-01 | Bookmarks, likes, feedback moved after the core workflow (still planned, not dropped) | Core collect → digest flow comes first | handoff §4 |
| before 2026-10-01 | Browser extension, logged-in content, page-change detection, scheduling → stretch / later | Keep the initial release achievable | handoff §4 |
| 2026-10-02 | No per-run limit on how many new items a digest covers (a proposed cap of 50 was rejected) | User wants every new item included after a long gap; progress display and batched topic grouping handle volume instead | User feedback on `add-core-digest-flow` proposals |
| 2026-10-02 | New future feature: let the user choose to output only the N most important items | User request; per-item summaries in the chosen design make ranking possible later | User feedback on `add-core-digest-flow` proposals |
| 2026-10-02 | Digest language is chosen by the user in Settings during initial setup (English, Simplified Chinese, same as original, or another language), instead of an environment variable defaulting to English | User request; the audience is not English-only. Cached item summaries now record their language so a language change re-summarizes instead of mixing languages | User feedback on the `add-core-digest-flow` plan |
| 2026-10-02 | Feed discovery also probes common feed locations (page URL + `.rss`, `/feed`, `/rss.xml`, `/atom.xml`, ...) when a page declares no feed | Sites like Reddit expose RSS without declaring it; users should be able to paste the normal page URL | User decision during `add-core-digest-flow` planning |
| 2026-10-02 | Text-based social media: Bluesky, Mastodon, and Reddit are supported through their RSS feeds in the first release; X is not supported | Verified live: Bluesky and Mastodon profiles declare RSS, and Reddit serves `/.rss`. X needs login (scraping is against its terms) or the paid X API ($0.005 per post read, no free tier, docs.x.com). Later options: a user-supplied X API key, or the browser extension | User question; decision to defer X pending the alpha |
| 2026-10-03 | The stored API key is used only with its stored base URL, and the instance accepts requests only for allowed hosts (`CATCHUP_ALLOWED_HOSTS`) | Review found that a DNS-rebinding page could repoint the provider URL and receive the stored key. The original design let missing fields fall back to stored values | Claude Code review of groups 2–3 |
| 2026-10-03 | Added requirements: readable titles for untitled entries; summaries focus on substance without metadata; output budgets that work with reasoning models; whole-site notice not shown on profile pages | First real test with DeepSeek and public sources (Bluesky, Mastodon, Reddit, a blog) found issues that mocked tests could not | Manual verification of `add-core-digest-flow` |
| 2026-10-03 | Deferred: extracting the linked article for Reddit link posts; Reddit rate-limit handling; a per-provider thinking toggle | Real-source behavior; larger than a fix | Manual verification of `add-core-digest-flow` |
| 2026-10-04 | Change `improve-source-reliability` narrowed to generic fetch reliability (User-Agent, 429/Retry-After, no duplicate fetch on confirm). The Reddit link-post extractor (#2) was dropped, and the README will state that Reddit support ends 2026-11-13 | Research found Reddit will stop all RSS on 2026-11-13 (TechCrunch 2026-09-30; Reddit Help Center), before the 2026-12-10 final demo. The generic work benefits every source | User decision after research |
| 2026-10-04 | "Deployed demo for course evaluation" (proposal) becomes local deployment: Docker image + setup docs, demo run on the developer's machine; no hosted instance | Course staff confirmed on the course forum that a locally deployed project is fine. Hosting would add access control and cost and would hit cloud-IP blocking | Course forum (staff answer); user decision |
